## 1. [P1] 删除非相邻重复顶点会改变实体面积

位置：`src/odbpp/clipper.py:365-371`，新增 `_to_grid()`。

取整后重复访问同一顶点，可能代表窄颈闭合或两个子轮廓相接。`seen` 将非相邻重复顶点直接删除，会把原来不相连的边连接起来，改变填充区域；后续 union 无法恢复已经丢失的路径。

复现输入是合法简单多边形，点序如下（传给 Ring 时反转为顺时针）：

```python
[(0,0), (2,0), (2,2), (1.00002,2), (1.00002,3), (2,3),
 (2,5), (0,5), (0,3), (1,3), (1,2), (0,2)]
```

输入面积 **8.00002 mm²**，两个矩形通过窄颈连接。四位小数网格下窄颈应退化，两个矩形的总面积应为 **8 mm²**；保留完整路径后交给 `pyclipper.SimplifyPolygon(..., PFT_NONZERO)` 得到该结果。当前 `snap_to_grid()` 却返回 **9 mm²**，`collapsed=0`，输出仍通过 Shapely 有效性检查。

这不是可归于离散化容差的小偏差：0.00002 mm 宽的连接消失，却额外生成 1 mm² 实体。现有“所有输出环有效”的测试会漏掉此问题。尚未定量追溯它对三份现有生产样本输出的影响。

建议：只删除相邻重复点和冗余闭合点；保留完整轮廓访问顺序，用 NONZERO 布尔规整/分解处理自接触。测试应同时检查区域对称差、面积和孔洞数，不能只断言 `is_valid`。

## 2. [P1] 整圆经过描边时仍丢失最后一段

位置：`src/odbpp/expand.py:470-473` 的新闭合路径，及下游 `src/odbpp/clipper.py:572-576`；根因是 `_to_clipper()` 在第 160-161 行删除重复闭合终点，而描边仍采用 `ET_OPENROUND`。

此次 `_path_points()` 已正确生成 360° 点列，但后续将其当成开路径处理，末尾回到起点的线段被移除。宽线时两端圆帽重叠，掩盖缺口；窄线时输出变成开口弧带，拓扑错误。

独立复现：MM 文件，圆心 (0,0)，起终点 (5,0)，符号 **r100（0.1 mm 线宽）**，默认弓高 0.005 mm。理论面积 π≈**3.141593 mm²**，应有一个岛和一个孔；当前面积 **3.102670 mm²**，**孔数为 0**，diagnostics 为空。面积近似可以有离散化误差，但圆环失去孔洞不是正常离散化误差。前次 r1000 用例仍约为 31.386 mm²，无法独立证明闭合正确。

建议：区分闭合中心线与开路径，闭合描边保留末段或使用合适的 closed-line 处理。增加线宽小于采样点间距的整圆用例，检查顺/逆时针、批处理/单图元入口及孔数。

## 3. [P2] 序列化精度可绕过新拓扑检查

位置：`src/odbpp/export.py:415`、`src/odbpp/export.py:476-477`，以及 `step_to_json()` 的独立 `round_digits` 参数。

新检查只在 `iter_step_previews()` 使用 `PreviewOptions.round_digits` 执行。`layer_to_json()` / `step_to_json()` 仍接受另一份精度参数并逐点取整，未验证其与预览分辨率相同；`StepPreview` 也不记录构建分辨率。公共 API 的正常组合因此可重新产生前次发现的退化多边形。

复现：用合法的 0.00002×1 mm Surface 替换内存中最小样本的一层图元，以 `PreviewOptions(round_digits=6)` 构建预览，再调用默认四位小数的 `step_to_json(job, preview)`。输出环面积为 **0**、`is_valid=False`，但 `area_mm2` 仍写 **0.00002**。输入 case 文件未改变。

建议：让预览携带并统一使用模型分辨率；序列化若请求不同精度，应重新规整并重算面积/边界，或明确拒绝。验证应覆盖构建与写出选项不一致的 API 路径。默认 CLI 将相同 digits 传给各阶段，因此本项不意味着默认 CLI 的现有三例输出已出现同样退化。
