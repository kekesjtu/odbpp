## 1. 非相邻重复顶点被删除导致面积改变

**根因**：`snap_to_grid` 的取整函数 `_to_grid()` 用 `seen` 集合删除**包括非相邻**在内的
所有重复顶点。被删的顶点往往正是自接触/窄颈的接触点：删除它会把原本只在一点相接的两条边
直接连起来，使填充区域改变。四位小数网格下窄颈退化时，两个矩形不是各自保留，而是被焊成
一个更大的矩形。

**修正**（`src/odbpp/clipper.py`）：

- `_to_grid()` 只删除**相邻**重复点与冗余闭合点，完整保留轮廓访问顺序；
- 自接触路径交给 Clipper 的 `PFT_NONZERO` 布尔规整，逐轮廓再过 `SimplifyPolygon`
  拆成严格简单环 —— 这一步 `snap_to_grid` 本来就有，但此前被 `_to_grid` 提前破坏了输入。

**验证**：审阅给出的 12 点窄颈多边形，输出面积 **8.0**（原 9.0）、**2 个岛、0 个孔**，
每个环均为 Shapely 有效且面积为正。刚挠板 `SPT` 层（曾因重复顶点被 Clipper 拒绝）导出成功，
`invalid_ring_count` 仍为 0，`export.degenerate_ring` 仍为 11 条（与修正前一致）。

## 2. 整圆描边丢失最后一段

**根因**：整圆弧的中心线首尾点相同，`_to_clipper()` 会去掉重复的闭合终点，而描边仍按
`ET_OPENROUND`（开路径加圆帽）处理。于是「最后一段」——从最后一个采样点回到起点——从未被扫掠。
线宽较大时两端圆帽重叠掩盖了缺口，线宽较小时就留下一条无孔的开口弧带。

**修正**（`src/odbpp/clipper.py`）：

- 新增 `_is_closed_centreline()`：按 1 nm 网格比较首尾点判断闭合中心线；
- `stroke_paths()` 对闭合路径使用 `ET_CLOSEDLINE`（连接首尾而非加端帽）；
- `sweep_polyline()` / `sweep_paths()` 对闭合路径补回起点，使 Minkowski 扫掠覆盖末段。

**验证**：审阅的 `r100`（0.1 mm 线）用例输出 **1 个孔**、面积 3.1405 mm²（理论 π）；
`r1000` 用例面积由 31.386 提升至 31.404 mm²（理论 10π≈31.416，差值来自离散化）。

## 3. 序列化精度可绕过拓扑检查

**根因**：只有 `iter_step_previews()` 用 `PreviewOptions.round_digits` 做几何规整；
`layer_to_json()` / `step_to_json()` 仍各自接受一份精度参数并逐点取整，两者不一致时
会把已规整的几何重新舍入，产生退化环，而 `area_mm2` 仍来自旧几何。

**修正**（`src/odbpp/export.py`）：

- `LayerPreview` / `StepPreview` 记录 `round_digits`（构建分辨率）；
- 序列化默认使用预览自身分辨率，写入的坐标就是被验证过的坐标；
- 显式要求不同精度时，`_serialised_rings()` 用 `snap_to_grid()` 在目标网格上**重新规整**，
  并从规整后的区域重算 `area_mm2` 与 `bounds_mm`；
- `write_outputs()` 未显式给出 `preview_options` 时，JSON 跟随预览分辨率。

**验证**：6 位分辨率下 0.00002 mm 宽的合法 Surface，默认序列化后 `area_mm2` 与
`Polygon(points).area` 均为 2e-05 且有效；显式要求 4 位时环被规整掉，`polygons=[]`、
`area_mm2=0.0`、`bounds_mm=null`，三者自洽。

## 4. 绝对 Z 起止坐标

**模型**（`src/odbpp/stackup.py`）：

- `ZExtent{start_mm, end_mm, thickness_known, source}`，Z 自叠层顶面（matrix 第一行板层）
  向下为正，单位为毫米；
- 按 matrix 行序自顶向下累加厚度：铜层优先 `.copper_weight`，回退 `.layer_dielectric`；
  介质层/阻焊层用 `.layer_dielectric`；钻孔不占厚度，其 Z 区间由 `START_NAME`/`END_NAME`
  指向的铜面位置给出；
- 结构性层（铜、介质、阻焊）厚度缺失时，`thickness_known=false` 并向下载荷；
  丝印/锡膏/补强/元件/文档属板面附着物，厚度缺失不影响铜面位置，不会污染整叠层。

**输出**：每层 JSON 增加 `z_mm`（板外图层为 `null`），step 级 `stackup[]` 同步给出；
`coordinate_system.z_axis` 声明方向约定；SVG 图层组与 HTML 行携带
`data-z-start/data-z-end/data-z-known`，HTML 信息面板显示 Z 区间，页眉显示已知板厚。

**验证**：`kicad-kitchen-sink` F.CU=[0.010,0.011]、DIELECTRIC_1 跨度 1.51 mm、全板 ≈1.532 mm；
`designodb-rigidflex` 各铜层 Z 连续、钻孔区间与所连铜面一致、`ASSEMT`（MISC 文档层）`z_mm=null`。

## 5. 英制 `.copper_weight` 的默认铜密度换算

**根因/需求**：`UNITS=INCH` 时 `.copper_weight` 是面密度（oz/ft²），没有长度就无法累加绝对 Z。

**修正**（`src/odbpp/units.py`）：

- 新增 `DEFAULT_COPPER_DENSITY_G_CM3 = 8.96`（电沉积铜标准密度）与
  `OUNCE_PER_SQ_FT_TO_G_PER_CM2`；
- `CopperWeight.thickness_mm` 对两种物理量都给厚度：公制 µm 直接换算；英制用
  `面密度 ÷ 密度`，1 oz/ft² → **0.034058 mm**；
- `copper_weight()` 接受可选 `density_g_cm3`；`as_dict()` 对英制结果标注
  `thickness_source="assumed_density"` 与 `assumed_density_g_cm3`。
- `kind` / `unit` 仍区分「厚度」与「面密度」两种物理量，密度是**公开假设**而非被抹平。

**验证**：设计刚挠板 `SIGNAL_1` 的 0.875563 oz/ft² → 0.0298191 mm，并被计入绝对 Z。

## 新增/变更的 JSON 字段（schema 仍为 `odbpp/preview-1`）

```jsonc
// coordinate_system
"z_axis": "increases downward from the top of the stack (matrix row 1), mm"
// layer 级新增
"z_mm": { "start_mm": 0.01, "end_mm": 0.011, "thickness_mm": 0.001,
          "thickness_known": true, "source": ".copper_weight" }
// copper_weight（英制）新增
"copper_weight": { "value": 0.875563, "kind": "areal_density_oz_ft2",
                   "unit": "oz/ft2", "thickness_mm": 0.029819,
                   "thickness_source": "assumed_density",
                   "assumed_density_g_cm3": 8.96 }
// step 级 stackup[] 每项新增 z_mm（同 layer 级结构）
```

无新增诊断码；`thickness_known=false` 即「位置基于假定零厚，非实测」的机器可读标记。

## 未覆盖与残留风险

- **未与独立 CAM 软件做像素/几何对照**：测试与静态检查通过不等于实体正确性验收通过。
- **Z 轴假定为「板厚连续、按行序累加」**：补强/局部层（如 STIFFENER）不改变全板 Z，
  但真实刚挠板局部叠层可能不同；本模型不表达局部 Z 变化。
- **假定铜密度 8.96 g/cm³**：与实际压延/电镀铜密度、表面处理有关的误差未建模；
  输出已记录所用密度，消费者可自行换算。
- **结构性层集合**（铜/介质/阻焊）为工程判定，规范未定义「哪些层构成板厚」。
- 钻孔仍不区分金属化/非金属化，`ROUT` 不参与扣孔、也无 Z。
