# 07 · 图片长宽比修复（2026-09-30）

修正对象：为「看看每块板的效果」而把全部 18 份输入导出成图时，发现
`masks/*.png` 与 `heatmaps/*.png` **都不按板的物理比例绘制** —— 同一条刚挠板的
两张图长宽比分别是 1.00 和 4.19，而板本身是 3.77。

修正基线：`3b65a44`（可视化功能与其文档）。
功能说明见 [`../equivalence/02-visualization.md`](../equivalence/02-visualization.md)；
同轮的另一项修复见 [`06-rectify-slab-loss.md`](06-rectify-slab-loss.md)。

## 结论摘要

| # | 问题 | 状态 | 主要验证 |
|---|---|---|---|
| 1 | 掩膜两轴同倍放大，非方形板被拉成正方形 | 已修 | 刚挠板 400x400 光栅：800x800 → 1509x400（比例 3.77 = 板） |
| 2 | 热图给每个有数据的行至少 1 px，网格比面板细时整体被拉伸 | 已修 | 同一层热图体区 720x400 → 720x191（与板、与掩膜一致） |
| 3 | 掩膜回调没有物理间距，画图的人无从保持比例 | 已修 | `mask_sink(name, mask, pixel_step_mm)` |

18 份输入的掩膜长宽比现在全部等于板的长宽比。

## 1. [P1] 掩膜被拉成正方形

**根因**（`visualize.auto_mask_scale` + `raster.LayerMask.top_down_rows`）：光栅沿
X、Y **各自**按 `px`、`py` 计数，两轴的物理间距往往不同。刚挠板 163.4 x 43.3 mm
在 400x400 光栅下 X = 0.408 mm/像素、Y = 0.108 mm/像素。整张图却用同一个整数
放大倍数复制两轴（`px*z` x `py*z`），于是输出正方形，把 3.77:1 的板画成 1:1。

**修改**：

- `raster.LayerMask.resampled_rows(width, height)`：两轴独立的最近邻缩放，
  顶行在前，源行按需缓存（放大时多行共用一行）；不改像素值、不插值。
- `visualize.mask_image_size(mask, pixel_step_mm)`：先取「长边约
  `MASK_TARGET_PX = 700`」，再要求两轴都至少 1 输出像素/光栅像素
  （`scale >= 1 / min(step)`），两者取大 —— 于是既保持比例，又不会把细走线或
  小孔抽样掉。仅当结果超过 `MASK_MAX_PIXELS = 4e6` 时才压缩。
  刚挠板因此得到 1509 x 400（比例 3.77），总像素数与原来的 800x800 同量级。
- `write_layer_mask()` 返回 `MaskImage(width, height, zoom_x, zoom_y)`：两个轴的
  缩放不再相同，整数不再够用；`--raster-scale N` 仍是显式的各向同性覆盖。

## 2. [P1] 热图被竖向拉伸

**根因**（`visualize._pixel_edges`）：为了让「窄到不足一像素但有值」的单元可见，
该函数把每个**有数据**的区间加宽到至少 1 px。网格行数（400）多于面板高度像素数
（720/3.77 ≈ 191）时，每一行都被撞到 1 px，面板整体变成 400 px 高：比例从 3.77
变成 1.80，同一块板的掩膜与热图再也对不上。

**修改**：改为只做「相对同一起点」的累积取整（`round((v - v0) * scale)`），
不再加宽。面板高宽比因此严格等于板的高宽比。代价是网格比面板细时，不足一像素的
单元没有自己的像素：**图是视图，CSV 才是数据**，要逐格看清就加大
`--heatmap-panel-width`（文档已写明）。

## 3. [P2] 掩膜回调缺少物理间距

**根因**：`mask_sink` 只交出 `(name, mask)`，而掩膜的像素间距只存在于等效器内部
（`EquivalenceResult.pixel_step_mm` 要到整轮结束才有），画图的人无从保持比例，
只能假装两轴相同。

**修改**：回调改为 `(name, mask, pixel_step_mm)`（`equiv.py` 把 `(dx, dy)` 随掩膜
一起交出）；CLI 顺手把信息行改成 `up to 1509x400 px, board proportions kept`，
显式各向同性缩放时仍打印 `zoom N px per raster pixel`。

## 4. 验证

| 验证 | 断言 |
|---|---|
| 合成非方形板 | 10 x 5 mm、4 x 4 光栅 → 700x350；两轴每毫米像素数相等，两轴 zoom 之比 = 间距之比 |
| 不欠采样 | 163 x 43 mm、400 x 400 光栅 → 两轴各 ≥ 1:1（1509 x 400），比例仍等于板 |
| 翻转与两轴缩放 | `resampled_rows(4, 2)` 顶行在前、X 翻倍 Y 不变；尺寸 0 报错 |
| 间距随掩膜传递 | 10 x 5 mm 板得到 `pixel_step_mm = (2.5, 1.25)` |
| CLI 端到端 | minimal 板 100 x 75 mm → `700x525`，信息行含 `up to 700x525 px` |

18 份输入实测掩膜长宽比：minimal 1.25、kitchen-sink 1.57、video 2.90、
刚挠板 3.77、两块 20 x 10 mm 小 KiCad 板 2.00 —— 全部等于板的长宽比；
热图面板同步（只差取整与图头/色标占用的高度）。

## 5. 教训

**「不让窄单元消失」与「保持比例」在像素数不够时无法同时满足**，必须先决定哪一个是
视图的契约。这里的选择是：比例是硬契约（否则人判断几何形状会被误导），
逐格可见性交给 `--heatmap-panel-width` 与 CSV。以后再加渲染特性时，
凡是要「保证某个单元可见」的规则，都要先问它会不会改变整体几何。
