# 图元、符号与几何语义

依据：Siemens *ODB++Design Format Specification*, Release 8.1 Update 4，[本地 PDF](../../reference/ODB++_Format_User_Guide.pdf)、[官方 PDF](https://odbplusplus.com/wp-content/uploads/sites/2/2024/08/odb_spec_user.pdf)。主要参考 p.34–40、p.92–93、p.164–180、p.187–205。

## 1. 图元、符号和轮廓是三个层次

- **Feature，图元**：放置在图元容器中的具体对象，例如一个 pad、一条线或一个 surface。
- **Symbol，符号**：可重复使用的形状定义，供 pad 放置或供 line、arc 沿路径拖拽。
- **Contour，轮廓**：由直线边和圆弧边组成的闭合区域，可以包含岛和孔，供 surface 等实体使用。

一个 `r200` 是符号名；`P 10 20 ...` 才是在指定位置放置这个符号的 pad 图元。一个 surface 直接以边界表达面积，不必先把它定义为符号。Profile 是受专门规则约束的 surface 容器，而不是第七种图元。（p.36–40、p.138、p.164）

图元可以出现在层、profile 和自定义符号等容器中，但各容器允许的图元类型不同。例如普通 features 支持多种记录，profile 限定为单个 surface。

## 2. 六类主要图元记录

下表省略属性和 UID 后缀；`<...>` 表示字段占位符。

| 记录 | 主体格式 | 几何意义 |
| --- | --- | --- |
| `P` | `P <x> <y> <apt_def> <polarity> <dcode> <orient_def>` | 放置一个符号实例 |
| `L` | `L <xs> <ys> <xe> <ye> <sym_num> <polarity> <dcode>` | 符号沿直线拖拽 |
| `A` | `A <xs> <ys> <xe> <ye> <xc> <yc> <sym_num> <polarity> <dcode> <cw>` | 符号沿圆弧拖拽 |
| `S` | `S <polarity> <dcode>`，随后是边界，最后 `SE` | 有面积的 surface |
| `T` | `T <x> <y> <font> <polarity> <orient_def> <xsize> <ysize> <width_factor> <text> <version>` | 由字体构成的文字 |
| `B` | `B <x> <y> <barcode> <font> <polarity> <orient_def> E <w> <h> ...` | 条码及可选附加文字 |

每类记录的完整字段说明见 p.169–180。`dcode` 是 Gerber dcode 或 Excellon tool number，未定义时为 0；它不是符号表索引。图元属性通过分号之后的索引赋值，详见[声明与属性](declarations-and-attributes.md)。

`polarity` 使用 `P/N`，分别表示正、负图元。同一行首的 `P` 是 pad 类型，行内的 `P` 则是极性，两者所在字段不同。

## 3. Pad：符号的一次放置

```text
UNITS=MM
$0 rect1000x500
P 10 20 0 P 0 8 30
```

该 pad 使用宽 1 mm、高 0.5 mm 的标准矩形，在 `(10 mm,20 mm)` 放置，顺时针旋转 30°，不镜像，图元极性为正。

普通 `apt_def` 是符号索引。需要 resize 时，写成三个字段：

```text
-1 <sym_num> <resize_factor>
```

例如：

```text
P 10 20 -1 0 20 P 0 8 0
```

`20` 是公制下 20 µm 的 resize 量，不是无量纲的“放大 20 倍”。p.170–172 将其描述为符号放大、缩小，并给出 mil/µm 单位；不能把字段名中的 factor 自动解释为普通乘法缩放系数。这里也不把该数值进一步擅自等同于“圆直径增加量”或“每条边偏移量”。

自定义符号的放置以其定义原点为插入点。规范 p.37 的箭头示例把原点设在箭头头部，说明自定义符号原点不必等于几何中心或包围盒中心。

## 4. Line 和 arc：路径与符号共同决定实体

### 4.1 拖拽而非无宽度路径

规范 p.38 规定通过符号中心沿直线或圆弧拖拽生成线、弧。因此端点坐标通常描述中心路径端点，不是最终实体最外边界。

```text
UNITS=MM
$0 r200
L 0 0 10 0 0 P 0
```

这里中心路径长 10 mm，圆符号直径为 0.2 mm。沿路径拖拽后形成宽 0.2 mm、两端为半圆的实体，其 X 范围是 `[-0.1,10.1] mm`，而不是 `[0,10] mm`。这是对拖拽定义的几何推导。

圆符号形成圆端，方符号形成方端。不能只保存中心线就认为已经表达了实际材料区域。

### 4.2 方形符号沿斜线拖拽

拖拽的形状由符号本身决定，不能把所有 line 都替换为沿路径法线等宽的圆笔刷结果。作为几何推导，边长 1 mm、保持轴向的方形沿 `(0,0) → (5,5)` 平移扫掠，其面积为：

```text
1×1 + 1×5 + 1×5 = 11 mm²
```

它和圆符号扫出的胶囊形不同，也不能未经说明把方符号自动旋转为“永远与路径对齐”的方端描边。

p.36 推荐对称符号用于 line、arc；p.38 更具体地规定 **arc 只能使用圆符号**。非对称标准符号或自定义符号用于 line 不受推荐；若数据包含这种线，规范要求结果应近似符号从起点到终点的扫掠，并由应用决定处理方式。不能据此断言任意复杂符号都能合法用于 arc。

### 4.3 Arc 的方向和整圆

Arc 由起点、终点、圆心、符号和方向定义：

```text
A 5 0 0 5 0 0 0 P 0 N
```

在 `$0` 已定义为圆符号的前提下，这是以 `(0,0)` 为圆心、从 `(5,0)` 逆时针到 `(0,5)` 的圆弧。`Y` 表示顺时针，`N` 表示逆时针。

当起点和终点相同，规范解释为 360° 圆弧，而不是零长度点：

```text
A 5 0 5 0 0 0 0 P 0 N
```

此图元的实体可能是圆环形区域，具体由中心路径半径和圆符号直径共同决定。不能因为它绕了整圆，就把圆内部全部填满。（p.40、p.172）

## 5. Surface：通过岛与孔定义面积

Surface 以 `S` 开始，以 `SE` 结束，必须至少包含一个 polygon。Polygon 边界以 `OB` 开始、`OE` 结束，其间是 `OS` 和 `OC`。（p.178–180）

| 记录 | 含义 |
| --- | --- |
| `S P 0` | 开始一个正 surface，dcode 未指定 |
| `OB <x> <y> I` | 从指定点开始一个岛边界 |
| `OB <x> <y> H` | 从指定点开始一个孔边界 |
| `OS <x> <y>` | 从当前点到给定终点的直线边 |
| `OC <xe> <ye> <xc> <yc> <cw>` | 从当前点到给定终点的圆弧边，并给出圆心及方向 |
| `OE` | 结束当前 polygon |
| `SE` | 结束整个 surface |

`OS/OC` 是**无宽度边界**，不引用符号表。与之相比，`L/A` 是有符号截面的图元。把 surface 边界当成有线宽的走线，会改变其面积。

一个外岛和一个孔的示例：

```text
UNITS=MM
F 1
S P 0
OB 0 0 I
OS 0 10
OS 20 10
OS 20 0
OS 0 0
OE
OB 5 3 H
OS 15 3
OS 15 7
OS 5 7
OS 5 3
OE
SE
```

这个 surface 面积为 `20×10 − 10×4 = 160 mm²`。`F 1` 统计一个 surface feature，而不是统计其两条 polygon 或所有边界记录的行数。

### 5.1 合法轮廓约束

规范 p.38–40 要求：

- 同一轮廓的岛不能相互接触或相交；孔应位于对应岛内，不能相互触碰或相交。
- 边界闭合，最后一个 OS/OC 的终点与 OB 起点相同。
- Polygon 至少有三个 segment，边长应大于零；圆弧起点、终点、圆心必须构成合法曲线。
- 岛边界顺时针，孔边界逆时针。
- 自相交多边形不合法；边只应在相邻边的公共端点相交。
- 记录按包含顺序排列：外岛先于其中的孔，孔先于孔内的岛。

孔内还可以有岛，不能把所有 `I` 区域先合并、再无条件扣除所有 `H` 区域而丢掉包含层级。一般 surface 的多岛能力也不改变 step profile 的单岛约束；详见[Profile 关系](profiles.md)。

## 6. 标准符号：名称本身携带参数

标准符号按预定语法从名称生成，不需要 `symbols/<name>/features`。一般形式为：

```text
<prefix><parameter>x<parameter>x...
```

`x` 是参数分隔符；参数不全是长度，也可能是角度、数量、百分比或角编号。长度参数按符号有效单位采用 µm/mil，小数使用 `.`。（p.36–37）

### 6.1 常用基础形状

以下公制示例假定有效符号单位为 M。

| 名称形式 | 示例 | 解释 |
| --- | --- | --- |
| `r<d>` | `r200` | 直径 0.2 mm 的圆 |
| `s<s>` | `s1000` | 边长 1 mm 的方形 |
| `rect<w>x<h>` | `rect1000x500` | 1×0.5 mm 矩形 |
| `rect<w>x<h>xr<rad>` | `rect1000x500xr100` | 四角圆角，圆角半径 0.1 mm |
| `rect<w>x<h>xc<rad>` | `rect1000x500xc100` | 带倒角的矩形 |
| `oval<w>x<h>` | `oval1000x500` | 1×0.5 mm 长圆，直边加半圆端帽 |
| `el<w>x<h>` | `el1000x500` | 1×0.5 mm 椭圆 |
| `di<w>x<h>` | `di1000x500` | 菱形 |
| `oct<w>x<h>x<r>` | `oct1000x1000x200` | 带角尺寸参数的八边形 |
| `tri<base>x<h>` | `tri1000x800` | 三角形 |

`oval` 和 `el` 不是同一种形状。标准圆的 `d` 是直径，不是半径。`r0` 在规范中是合法的零面积符号，不能只因面积为零就声称其名称不合法。（p.37、p.187–192、p.200）

### 6.2 环形、thermal 及其他族

| 类别 | 代表语法 | 主要参数含义 |
| --- | --- | --- |
| 圆环 | `donut_r<od>x<id>` | 外径、内径 |
| 方环 | `donut_s<od>x<id>` | 外边长、内边长 |
| 方外圆内环 | `donut_sr<od>x<id>` | 外方尺寸、内圆直径 |
| 矩形环 | `donut_rc<ow>x<oh>x<lw>` | 外宽、外高、环宽 |
| 长圆环 | `donut_o<ow>x<oh>x<lw>` | 外长圆宽高和环宽 |
| 圆 thermal | `thr<od>x<id>x<angle>x<num_spokes>x<gap>` | 外内径、角度、辐条数量及间隙 |
| 方 thermal | `s_ths<os>x<is>x<angle>x<num_spokes>x<gap>` | 外内尺寸、角度、数量及间隙 |
| 钢网开口 | `hplate...`、`rhplate...`、`fhplate...`、`dshape...` | 形状尺寸和局部切角、圆角等参数 |
| 组合形状 | `cross...`、`dogbone...`、`dpack...` | 线宽、连接位置、间隔、行列数量等 |
| 对准图形 | `moire...` | 环宽、环间距、环数量、线宽、线长、角度 |
| 钻孔轮符号 | `hole<d>x<p>x<tp>x<tm>` | 孔径、金属化状态及正负公差 |

这是分类导览，不是完整参数表。Thermal 的各个族对角度、数量和空气间隙有独立定义及限制，不能只按前缀猜测其几何。其实体在铜层上的材料含义还受层极性和图元极性影响。（p.189–201）

### 6.3 角编号与选角

圆角/倒角符号可用 `x<corners>` 指定部分角；省略时表示全部角。角编号从右上角开始，逆时针依次为 1、2、3、4：

```text
+---------+
|2       1|
|         |
|3       4|
+---------+
```

例如 `rect1000x500xr100x13` 表示对 1、3 号角应用相应圆角。这里的 `13` 是角编号组合，不是长度 13，也不是二进制位掩码。各符号的尺寸合法性还要满足相邻圆角不相交等限制。（p.187–188、p.201–204）

## 7. 自定义符号：可复用的单层图形

自定义符号的形状定义位于：

```text
symbols/<symbol_name>/features
```

符号还可以有自身的 attrlist。其 features 文件采用与层 features 相似的结构，可以包含多个图元，并引用其他自定义符号。循环引用被禁止。（p.37、p.92–93）

例如：

```text
# symbols/connector_target/features
UNITS=MM
$0 r200
P -1 0 0 P 0 8 0
P 1 0 0 P 0 8 0
```

在某层引用：

```text
UNITS=MM
$0 connector_target
P 10 20 0 P 0 8 0
```

忽略其他变换时，两个圆分别位于 `(9,20)` 和 `(11,20)` mm。符号定义一次，可以被多层、多位置、多方向重复引用；每个文件的 `$0` 都属于该文件自己的符号表。

标准符号的前缀由规范保留，不能故意给自定义符号使用保留前缀，再依赖“标准参数不合法”让它变成自定义符号。判断名称需要按完整命名规则，不能只看第一个字母。（p.37）

## 8. 旋转、镜像与放置顺序

Pad 的方向编码见 p.170–171：

| 编码 | 含义 |
| --- | --- |
| `0/1/2/3` | 不镜像，分别旋转 0°/90°/180°/270° |
| `4/5/6/7` | 镜像，分别配合 0°/90°/180°/270° 旋转 |
| `8 <angle>` | 不镜像，任意角度旋转 |
| `9 <angle>` | 镜像，任意角度旋转 |

规范保留了 0–7 的旧数据编码，并说明 8、9 后跟一个独立角度值。`8 30` 是两个字段，不能读成数字 830。

角度采用度，正方向为顺时针。当同时旋转和镜像时，先旋转、后镜像。（p.34–35）

规范把镜像称为 x-axis mirroring，并明确说明是左右翻转、改变 x 坐标。为避免和常见数学轴命名混淆，应以这个坐标效果为准。在通常 X 向右、Y 向上的坐标表达中，顺时针旋转和该镜像可写成以下数学说明：

```text
x_rot =  cos(θ)·x + sin(θ)·y
y_rot = -sin(θ)·x + cos(θ)·y

镜像时：x_mirror = -x_rot, y_mirror = y_rot
最后加上实例的放置坐标。
```

实例变换应围绕符号定义原点进行，而不是擅自围绕几何包围盒中心。Step 的 MIRROR/FLIP 属于 stephdr 的另一层实例关系，不能只套用 pad 的方向字段解释。

## 9. 图元极性与层极性

### 9.1 图元极性是有顺序的覆盖和擦除

p.39 规定：正图元覆盖容器内此前图元的对应区域，负图元擦除此前图元的对应区域。作为集合推导，若当前图形为 `G`、新图元实体为 `F`，则：

```text
P：G_next = G ∪ F
N：G_next = G \ F
```

这意味着记录顺序有意义。例如“正大矩形 → 负小圆 → 正小焊盘”，最后一个焊盘可以填回先前擦除区域的一部分。不能先把所有正图元合并，再一次性扣除所有负图元。

### 9.2 符号内部的孔是透明的

标准符号是正的填充形状，其内部孔按定义透明。（p.37）例如把正圆环符号放在已有正铜面上，圆环中央不会自动擦掉原先的图形；它只是不增加该处的覆盖。要擦除已有图形，需要相应的负图元操作。

Surface 的孔同样界定该 surface 自身不覆盖的区域，不应无条件解释成对整个容器此前图元的一次全局擦除。

### 9.3 Matrix 层极性决定材料解释

Matrix 的 `POLARITY=POSITIVE|NEGATIVE` 与图元上的 `P/N` 是不同层次。（p.66）

- 对正性铜层，图形表示铜。
- 对负性层，图形表示层压材料区域；常见于电源/地层，pad 图形可能代表铜间隙，背景为铜。
- SOLDER_MASK、MASK 是特殊情况：要求 POSITIVE，图形表示物理掩模的开口。
- Matrix 层极性不等于输出光绘底片的极性设置。

因此看到 `P` 只能确定图元的图形合成操作，不能脱离层类型、层极性和轮廓就认定它在所有场景下都是“增加铜”。Profile、层图形和层材料语义应共同阅读。

## 10. Text 与 barcode 也是图元

`T` 定义位置、字体、极性、方向、尺寸、线宽因子、字符串及版本；字符串可以包含 `$$DATE-MMDDYY` 等动态文本变量。它和 `&` 属性字符串表的元数据不同。（p.173–176）

`B` 定义条码类型、字体、方向、单元宽度、高度、校验和标记、背景反转及附加可读文字等。规范本节列出的条码名称为 UPC39。其完整字段应按 p.176–178 阅读，不能用普通文本宽高替代条码几何。

这些图元的存在说明，ODB++ 图形不只有铜焊盘、走线和填充面；同一格式还承载标识、装配和制造辅助图形。具体材料意义始终依赖所在层和对应属性。
